## What it is

GeradorOne is a web app for people who prepare teaching materials: teachers, workbook authors, courses, and schools. The user describes the material (subject, topic, audience, goal, type, visual style) and the app builds a detailed prompt, with one image per page, to paste into an image generation tool.

Users who register their own AI key (BYOK: OpenAI, Google Gemini, or Anthropic) can request the finished material as PDF or HTML, generated by the server with that key. The app has no global key: each person uses and pays for their own.

> GeradorOne does not validate curriculum content. The prompts ask the AI not to invent codes, sources, norms, or data, but whoever uses the result must review it.

## Features

**Languages**

- Interface, FAQ, emails, and prompts in Brazilian Portuguese, English, Spanish, German, and Italian, with a flag selector on the sign-in screen and in the menu. The chosen language also applies to the text the prompt asks for inside the images, and it is saved to the account. Terms and Privacy policy exist only in Brazilian Portuguese.

**Workbook**

- 12 material types plus an Other option, including teaching workbook, review material, activity book, study guide, teaching sequence, and teacher's guide.
- Subject, topic, audience, learning objective, and five depth levels (from Introductory to Complete).
- 12 illustration styles with thumbnails (Cartoon, Hand-drawn, Textbook, Realistic, Educational 3D, and others) and a palette chosen separately.
- Formats for A4 print, screen, and 16:9 presentation.
- Graphic resources: mind maps, diagrams, illustrations, infographics, charts (only with verifiable data), comparison tables, timelines, icons, and signage, with controls for frequency and visual depth.
- BNCC skill selector (the Brazilian national curriculum standard), with filters by stage, grade, and subject area and text search, over a local copy of the 1,721 official codes. The app checks the codes typed in and carries the official text into the prompt.

**Cover:** prompt for the front cover art, with the exact cover texts and the same style table.

**Result and export**

- The prompt appears in the result panel, with one-click copy and download as TXT, JSON, or PDF.
- "Improve with AI" rewrites the prompt with the user's key.
- "Generate material with AI" produces the complete material as a PDF or standalone HTML, with up to three AI-generated images embedded. Mermaid diagrams and Chart.js charts described by the AI are drawn on the server, offline, and enter the file as SVG and image.
- With Anthropic, the app generates text only: "AI images" must be set to "Do not use AI-generated images".

**Accounts and projects**

- Sign-in by email and password, administrator and user roles, mandatory password change on first access.
- Projects saved per user (My projects), with JSON import and export.
- Self-registration and password recovery by a code sent by email, when SMTP is configured. Without SMTP, only the administrator registers users and resets passwords.
- "My account": profile, password change, "Download my data (JSON)", and deletion of the user's own account.
- Terms of use and Privacy policy (`public/termos.html` and `public/privacidade.html`), with acceptance recorded on the account. The texts are templates without legal review: whoever hosts an instance must adapt them.

**Interface**

- Pages Home (first-steps guide, with an animated demo and a sample prompt), About, FAQ with search, and Support (a form with attachments that sends the message by email).
- Six color themes: Paper, Graphite, Chalkboard, Ink blue, Sepia, and High contrast, or follow the system. See [docs/DESIGN.en.md](docs/DESIGN.en.md).
- Responsive interface for desktop, tablet, and phone, in Brazilian Portuguese.

**Administration:** the Settings screen has the tabs Users (create, edit, activate, deactivate, reset password, and delete), Email (SMTP), with a test send, and Backup, which shows the status of the database copies.

## How it works

1. The user fills in the Workbook or Cover form. The prompt is built in the browser, without calling the server or the AI.
2. They copy the prompt or download the file and use it in the image tool they prefer.
3. If they have an AI key registered, they can request "Generate material with AI". The server decrypts the key only in memory, calls the provider, sanitizes the returned HTML and, for PDF, converts it with the container's Chromium.

## Quick start

Prerequisites: Docker with the Compose plugin.

```sh
git clone https://github.com/Epaminondaslage/geradorOne.git
cd geradorOne
```

Create a `.env` file next to `compose.yaml` with permission 600 (`chmod 600 .env`). The minimum is this:

```env
POSTGRES_PASSWORD=replace-with-a-random-value
APP_SECRET=replace-with-32-or-more-random-characters
ADMIN_NAME=Your Full Name
ADMIN_EMAIL=you@your-domain.com
ADMIN_PASSWORD=a-password-with-8-or-more-characters
```

To generate random values:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`compose.yaml` connects the app to an external network called `coolify`, used by the reverse proxy of the development environment. On a machine that does not have this network, create it once (the Traefik labels have no effect without that proxy):

```sh
docker network create coolify
docker compose up -d --build
```

The app is available at `http://your-server:8123`. Sign in with `ADMIN_EMAIL` and `ADMIN_PASSWORD`; a password change is required on first access. If `ADMIN_PASSWORD` is empty or has fewer than 8 characters, the app generates a temporary password and prints it once in the log:

```sh
docker compose logs gerador-one | grep setup
```

After that, each user registers their own key under **My AI key** to use the AI features.

If you lose administrator access, generate an emergency temporary password:

```sh
docker exec gerador-one node scripts/reset-password.js ADMIN-EMAIL
```

## Configuration

All variables live in `.env`, which never goes to Git. Do not publish that file, the API keys, or the `APP_SECRET`.

| Variable | Required | What it is for |
|---|---|---|
| `POSTGRES_PASSWORD` | yes | Database password. Without it, `docker compose` refuses to start. |
| `APP_SECRET` | recommended | Master key (32 or more characters): encrypts the AI keys and signs the sessions. Without it, the app generates `runtime/secret.key`, a less secure option. |
| `ALLOW_NEW_SECRET` | no | `true` accepts a new master key for one startup (see below). |
| `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PHONE`, `ADMIN_PASSWORD` | no | First administrator, created only when the database has no users. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_REQUIRE_TLS`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | no | Email sending (registration, password recovery, support). Default port 587; `SMTP_SECURE=true` for direct TLS on 465; `SMTP_REQUIRE_TLS=true` to require STARTTLS. |
| `APP_URL` | no | App address that appears in the emails. |
| `CONTACT_EMAIL` | no | Contact address shown in emails, the Terms, the Policy, and the FAQ. |
| `DOMINIO` | only in `compose.prod.yaml` | Domain of the HTTPS certificate issued by Caddy. |

SMTP can also be configured by the administrator on the **Settings → Email (SMTP)** screen. What is saved there takes priority over `.env`, and the password is stored encrypted in the database. To test from the terminal: `docker exec gerador-one node scripts/test-smtp.js --verify`.

**Be careful with `APP_SECRET`.** The app stores a fingerprint of the key in `runtime/secret.check` and refuses to start if it changes, because the saved AI keys would become unreadable. To change the key on purpose, start once with `ALLOW_NEW_SECRET=true` and then remove the variable. Keep a copy of `.env` separate from the database backup.

## Self-hosting with HTTPS

`compose.prod.yaml` starts the app, Postgres, and a Caddy that issues and renews the Let's Encrypt certificate for the domain in `DOMINIO`:

```sh
docker compose -f compose.prod.yaml --env-file .env up -d --build
```

The domain's DNS must point to the server's public IP, and ports 80 and 443 must reach the Caddy container. Port 8123 stays published over unencrypted HTTP; do not forward it to the internet. With this file, the Backup tab expects the copy status files in the `monitor/` folder and warns when they do not exist.

## Database and backup

Users, projects, and settings live in a Postgres 17 (the `db` service), in the `pgdata` volume. The database exists only on Docker's internal network and publishes no port. The schema is created and updated automatically at startup, through versioned migrations in `lib/db.js`.

Backup:

```sh
scripts/backup-db.sh
```

The script writes `backups/geradorone-YYYYMMDD-HHMM.sql.gz` (permission 600) and deletes copies older than 14 days. The folder changes with `BACKUP_DIR`; schedule the script in the server's cron. To restore into an empty database:

```sh
zcat backups/FILE.sql.gz | docker exec -i gerador-one-db psql -U geradorone geradorone
```

## Architecture and folder structure

Node.js 22 with no framework and no build step: `node:http` on the server, plain JavaScript in the browser, `pg` for the database, `pdfkit` for the prompt PDF, `nodemailer` for email, and Chromium to convert the generated HTML to PDF. The container runs as an unprivileged user, with a read-only file system and no capabilities.

```text
.
├── server.js              # HTTP server, /api routes, session, AI, and PDF
├── lib/                   # database, users, projects, cryptography, email, support, diagrams
├── public/                # static interface (HTML, CSS, app.js, FAQ, themes, BNCC data)
├── vendor/                # Mermaid and Chart.js, used by the server to draw diagrams
├── scripts/               # tests, backup, emergency password, SMTP test, BNCC data
├── test/                  # tests against a real Postgres
├── docs/                  # code map, visual identity, icon standard, prompt examples
├── deploy/Caddyfile       # HTTPS proxy for compose.prod.yaml
├── compose.yaml           # app + database
├── compose.prod.yaml      # app + database + Caddy
└── Dockerfile
```

The [code map](docs/CODEBASE_MAP.en.md) describes the API routes, the data model, the flows, and the open points. The visual identity and themes are in [docs/DESIGN.en.md](docs/DESIGN.en.md), and the icon button pattern in [docs/PADRAO_ICONES.en.md](docs/PADRAO_ICONES.en.md). There is one sample prompt per material type in [docs/exemplos/](docs/exemplos/).

## Development and tests

```sh
npm ci
npm test            # starts a disposable Postgres 17 in Docker, runs the suite, and removes the container
npm run test:node   # uses your own Postgres, set in TEST_DATABASE_URL
```

To run the app outside Docker, set `DATABASE_URL` pointing to a Postgres and run `npm start` (it listens on `127.0.0.1:3000`). The PDF conversion of the AI mode needs an installed Chromium (`CHROMIUM_PATH`).

The code is copied into the image at build time: after changing `server.js`, `lib/`, or `public/`, rebuild with `docker compose up -d --build`.

## How to contribute

Contributions are welcome. The workflow, the commit style, and the rules are in [CONTRIBUTING.en.md](CONTRIBUTING.en.md). In short: open an issue to discuss the change, send a pull request to `main`, write commits in Portuguese in the `feat:`, `fix:`, or `docs:` style, and keep `npm test` passing.

## Security

If you find a vulnerability, do not publish the details in a public issue. Use GitHub's private reporting (the Security tab, "Report a vulnerability"); the step-by-step is in [SECURITY.en.md](SECURITY.en.md).

Design points worth knowing: passwords hashed with scrypt, AI keys encrypted with AES-256-GCM and never returned to the browser (only the last 4 characters), session in an `HttpOnly` and `SameSite=Lax` cookie, a content security policy (CSP) with no inline scripts, and AI-generated HTML filtered by an allowlist before PDF conversion.
